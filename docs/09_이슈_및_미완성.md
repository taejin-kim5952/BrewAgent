## 알려진 이슈

| 이슈 | 상태 | 설명 |
|---|---|---|
| **패키지명 충돌** | ✅ 해결됨 | `platform/` → `rag/`로 변경. Python 표준 `platform` 모듈과 이름 충돌로 uvicorn `--reload` 모드에서 `AttributeError: module 'platform' has no attribute 'uname'` 발생했었음 |
| **Pydantic 경고** | ⚠️ 무해 | `model_name`, `model_fast`, `model_full` 필드가 `model_` 네임스페이스와 충돌. 동작 영향 없음. 수정하려면 각 Config 클래스에 `model_config = ConfigDict(protected_namespaces=())` 추가 |
| **StorageConfig 상대경로** | ✅ 해결됨 | `base_dir: "../storage"`가 cwd 기준으로 잘못 해석되던 버그. `__file__` 기반 절대경로 계산으로 수정 |
| **`gemma4:latest` CPU 폴백** | ⚠️ 환경 이슈 | RTX 3050 4GB VRAM에 9GB 모델은 안 들어가서 CPU만 사용 → 매우 느림. 작은 모델 사용 권장 |
| **timeout 후 좀비 task** | ❌ 미해결 | LLM 호출 timeout 시 task가 status='extracting'으로 남음. 서버 재시작으로만 정리 가능 |

### Stale 가이드 자동 정리
서버 시작 시 `extracting` 상태인데 30분 이상 갱신 안 된 가이드 자동 'failed' 마킹.
```python
# server/dependencies.py.startup() 에 추가 가능
async def cleanup_stale_guides():
    threshold = datetime.utcnow() - timedelta(minutes=30)
    await db.execute(
        "UPDATE guides SET status='failed', error_msg='timeout (stale)' "
        "WHERE status IN ('parsing','extracting') AND updated_at < ?",
        (threshold.isoformat(),)
    )
```

### 동시성 제어
현재 백그라운드 task가 동시에 여러 개 실행 가능. LLM 호출이 중첩되면 Ollama 큐가 막힘. 작업 큐 도입 필요.
```python
# 권장: asyncio.Semaphore로 동시 호출 1로 제한
_llm_lock = asyncio.Semaphore(1)
async with _llm_lock:
    response = await backend.generate(...)
```

## 회피 가능한 트러블슈팅

### "parsing 0%에서 멈춤"
원인: `python-docx` 또는 `python-pptx` 미설치
해결:
```powershell
.venv\Scripts\python.exe -m pip install python-docx==1.1.2 python-pptx==1.0.2
```

### "Q&A 0개 생성됨"
원인: 서버가 옛 모델을 들고 있음 (재시작 안 함) + 큰 모델 CPU 폴백
해결:
1. `Ctrl+C` 또는 `taskkill /f /im python.exe`
2. `local.yaml` 모델 변경 (예: `gemma3:1b`)
3. 서버 재시작

### "GPU 사용 안 함"
원인: 모델이 VRAM 4GB보다 큼 → Ollama가 CPU 폴백
확인:
```bash
curl http://localhost:11434/api/ps
# size_vram=0 이면 CPU만 사용 중
```
해결: 작은 모델 (gemma3:1b, qwen2.5-coder:1.5b 등)로 교체

### "Continue.dev에서 한자 섞임"
원인: Qwen 계열 모델의 알려진 한국어 문제
해결: gemma 계열 또는 한국어 특화 모델(exaone-deep, kitad 등) 사용
