## 4-1. AppContainer (`server/dependencies.py`)

전체 컴포넌트의 싱글톤 컨테이너. 서버 시작 시 `startup()`, 종료 시 `shutdown()` 호출.

```python
container = get_container()  # 어디서든 싱글톤 접근

# 주요 멤버
container.settings           # Settings (전체 설정)
container.embedder           # Embedder (sentence-transformers)
container.metadata_store     # MetadataStore (SQLite + FTS5)
container.pipeline           # IngestPipeline (문서 인덱싱)
container.intelligence       # QueryIntelligence (의도 분석)
container.context_optimizer  # ContextOptimizer (중복 제거)
container.llm_router         # LLMRouter (모델 선택)
container.prompt_builder     # PromptBuilder (프롬프트 조립)
container.eval_engine        # EvaluationEngine (자동 채점)
container.knowledge_store    # KnowledgeStore (FAQ)
container.response_cache     # ResponseCache (TTL 캐시)
container.interaction_logger # InteractionLogger (대화 + 수동 입력)
container.guide_store        # GuideStore (가이드/규칙/Q&A)
container.exporter           # JSONLExporter
container.tool_executor      # ToolExecutor
container.get_faiss_store(namespace)  # 네임스페이스별 FAISSStore
```

**초기화 순서**:
Settings → Embedder → NamespaceManager → MetadataStore → IngestPipeline → QueryIntelligence → ContextOptimizer → LLMRouter → PromptBuilder → EvaluationEngine → KnowledgeStore → ResponseCache → InteractionLogger → GuideStore → JSONLExporter → ToolExecutor

`startup()`에서 `metadata_store.init()`, `interaction_logger.init()`, `guide_store.init()` 호출하여 SQLite 테이블 생성.

## 4-2. 채팅 처리 흐름 (`server/routes/chat.py`)

```
1. POST /v1/chat/completions 수신
2. QueryIntelligence.analyze(query, history)
   → QueryAnalysis {intent, complexity_score, rewritten_queries, filters}

3. HybridRetriever.retrieve(analysis, namespace)
   → 각 rewritten_query마다 FAISS 벡터 검색
   → 원본 쿼리로 FTS5 BM25 검색
   → 점수 합산 (vector_weight * vector + bm25_weight * bm25)
   → 상위 top_k 청크 선택

4. ContextOptimizer.optimize(chunks, query, max_tokens)
   → Jaccard 유사도 0.9 이상 청크 중복 제거
   → 토큰 예산(max_context_tokens=4096) 초과 시 하위 청크 제거

5. PromptBuilder.build(query, chunks, intent, history)
   → 의도별 시스템 프롬프트 + 청크 컨텍스트 + 대화 기록 + 질문 조합

6. LLMRouter.route(analysis)
   → complexity < 0.3 → fast 모델
   → complexity < 0.7 → full 모델
   → complexity ≥ 0.7 → OpenAI 폴백 (force_local=true면 full)

7. backend.generate() 또는 stream() (SSE)

8. [백그라운드 asyncio.create_task] _log_and_eval()
   → EvaluationEngine.evaluate() (relevance + faithfulness + code_quality)
   → InteractionLogger.log() + update_eval_score()
```

## 4-3. 인제스트 파이프라인 (`ingest/pipeline.py`)

### 지원 파일 형식

| 확장자 | 파서 | 청킹 전략 |
|---|---|---|
| `.pdf` | PyMuPDF | sliding_window (512 토큰) |
| `.docx` | python-docx | sliding_window |
| `.pptx` | python-pptx | AS_IS (슬라이드 단위) |
| `.xlsx`, `.xls` | openpyxl → 마크다운 테이블 | AS_IS (시트 단위) |
| `.jpg`, `.png` | pytesseract OCR | sliding_window |
| `.java`, `.sql`, `.py` | CodeParser | AS_IS (메서드/구문 단위) |
| `.txt`, `.md`, `.csv` | TextParser | sliding_window |
| **`.zip`, `.tar.gz`** | 자동 추출 → 내부 파일 재귀 인제스트 | 각 파일별 |

### 청킹 파라미터 (`default.yaml`)

```yaml
chunking:
  default_strategy: "sliding_window"
  chunk_size: 512                # 기본 청크
  chunk_overlap: 64              # 슬라이딩 윈도우 겹침
  code_chunk_size: 1024          # 코드 파일
  table_chunk_size: 256          # 테이블
```

### 압축 파일 처리

`pipeline._is_archive()` 체크 후 `ingest_archive()` 호출:
1. `tempfile.mkdtemp()` 으로 임시 디렉터리 생성
2. zipfile/tarfile 로 압축 해제 (Zip-slip 방어 + 1GB + 1000파일 가드)
3. 추출된 모든 파일 순회 → 각 파일에 `ingest_file()` 재귀 호출
4. 결과 집계 후 `shutil.rmtree(temp_dir)` 정리

## 4-4. 품질 평가 (`evaluation/`)

채팅 응답마다 백그라운드로 자동 실행. `interactions.db`에 점수 저장.

| Scorer | 공식 | 통과 기준 |
|---|---|---|
| **relevance** | `\|query_words ∩ answer_words\| / \|query_words\| × 2` | ≥ 0.1 겹침 |
| **faithfulness** | `\|answer_words ∩ context_words\| / \|answer_words\| × 2` | ≥ 0.2 근거 |
| **code_quality** | Python 코드 블록 AST 파싱 성공률 | 파싱 오류 0개 |

EvalEngine은 비동기 병렬로 모든 scorer 실행:
```python
results = await asyncio.gather(*[s.score(...) for s in scorers])
overall = mean(r.score for r in results)
```

> **NOTE**: 현재 단어 겹침 기반 휴리스틱. LLM-as-Judge로 교체하면 정확도 크게 향상 ([9. 미완성 항목](09_이슈_및_미완성.md) 참고).

## 4-5. LLM 복잡도 라우팅 (`llm_router/`)

### 복잡도 점수 (`query/intelligence.py`)

```python
complexity_score = (
    min(len(query) / 500, 1.0) * 0.5     # 길이 기여
    + (0.1 if has_complex_keyword else 0)  # "설계", "아키텍처", "리팩토링" 등
    + (0.2 if multiple_questions else 0)   # ?가 2개 이상
)
# 결과: 0.0 ~ 1.0
```

### 라우팅 결정

```
score < 0.3              → LOCAL_FAST   (빠른 답변, 단순 질문)
0.3 ≤ score < 0.7        → LOCAL_FULL   (정확한 답변, 중간 복잡도)
score ≥ 0.7              → EXTERNAL     (OpenAI 등, force_local=false 시)
                          → LOCAL_FULL   (force_local=true 시)
```

### 백엔드 구현

`OllamaBackend`:
- `generate()`: POST /api/chat (stream=false) → 응답 한 번에 받기
- `stream()`: POST /api/chat (stream=true) → 토큰 단위 yield
- `is_available()`: GET /api/tags (5초 timeout)

`OpenAIBackend`: SSE 형식 처리, `Authorization: Bearer {key}` 헤더.

## 4-6. 설정 오버라이드 (`configs/`)

`default.yaml`을 기본값으로, `local.yaml`이 있으면 **딥 머지**로 오버라이드.

### 작동 방식
```python
def load_settings():
    data = _load_yaml("default.yaml")
    local_data = _load_yaml("local.yaml")  # 없으면 빈 dict
    merged = deep_merge(data, local_data)  # local이 default를 덮어씀
    return Settings(**merged)
```

### 두 파일의 역할
| 파일 | 역할 | git 추적 |
|---|---|---|
| `default.yaml` | 모든 사용자 공통 기본값 | ✅ 추적 |
| `local.yaml` | 개인 PC 환경 오버라이드 | ❌ gitignore |

### 로컬 설정 예시 (`local.yaml`)
```yaml
ollama:
  model_fast: "gemma3:1b"      # 다른 모델로 교체
  model_full: "qwen3.5:4b"
  base_url: "http://192.168.1.100:11434"  # 원격 Ollama

routing:
  force_local: false           # OpenAI 폴백 허용
  complexity_threshold_fast: 0.4

retrieval:
  top_k: 15
  vector_weight: 0.6
```

### `StorageConfig.path` 해석 규칙
- 절대 경로면 그대로 사용
- 상대 경로면 `rag/configs/` 기준 3단계 상위 + `storage/` → 항상 설치 루트의 `storage/` 폴더

### 머지 동작 주의
- **딕셔너리(중첩 객체)**: 키 단위로 머지
- **리스트**: 통째로 교체 (부분 추가 X)
